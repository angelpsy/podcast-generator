# Проверка Android UI без слепых цепочек

Используйте `python3 tools/device-ui.py scenario.json --audit-dir .tooling/<проверка>`.
Нужен один Pixel в ADB (`-d`); для явного выбора есть `--serial`. Старый helper в
`.tooling/device-ui.py` отключён. Не запускайте рядом прямые `adb input` или другой
UI-runner и не управляйте телефоном вручную, пока выполняется сценарий.

Пример чтения экрана и перехода с главной страницы:

```json
{"steps": [
  {"action": "snapshot", "expect": ["Что изучим?"]},
  {"action": "tap", "target": "8, Очередь", "before": ["Что изучим?"], "expect": ["Очередь создания", "Незавершённых: 8 / 100"]}
]}
```

Сначала отдельным snapshot проверьте фактический счётчик/названия. Для `before`
и `expect` выбирайте уникальные заголовки или состояние, а не подпись вкладки,
которая присутствует на всех экранах. Число в accessibilityLabel вкладки зависит
от текущих заданий.

Для проверки исчезновения ошибки задавайте `expect_absent`; одного прежнего
заголовка в `expect` недостаточно. Аналогично есть `before_absent`.

Доступны `snapshot`, `tap`, `back`, `scroll` (`direction: up/down`, до 10
`max_swipes`). Изменяющий UI шаг требует before/expect. `tap` требует один
видимый включённый элемент, два свежих снимка с одинаковыми координатами и
проверку результата. Любая ошибка прерывает весь сценарий; не объединяйте
несколько вызовов shell без остановки при ошибке. На весь сценарий удерживается
эксклюзивная блокировка `.tooling/device-ui.lock`; XML имеет уникальное имя.

Управление очередью (enqueue/resume/pause/cancel/recovery) требует также
`"queue_command": true`. Для физических проверок используйте только отдельные
проверочные задания. **Не нажимайте общий Resume на пользовательской очереди**
ради проверки кнопки: этот контракт проверяется в изолированных тестах.

`actions.jsonl` хранит UTC-время, run/step, цель, прямоугольник и результат
проверки; `sending` означает лишь отправленный tap, а `verified` — совпавшее
ожидаемое состояние. JSON-снимки содержат только узлы приложения, email скрыт.
Фокус проверяется до и после чтения; браузер и другие приложения не снимаются.
Координатный tap не атомарен с изменением экрана: при неожиданном результате
проверка останавливается, результат требует разбора, успех не предполагается.

Команды приложения дополнительно пишутся в ограниченный журнал
`noBackupFilesDir/podcast/queue-audit.jsonl` (одна ротация, по 128 KiB) и logcat
с тегом `QueueAudit`. Он содержит commandId, UTC-время, action, source,
scope/targetId, result, affected и счётчики статусов. Темы, тексты, токены и
произвольные сообщения ошибок не записываются. `source=ui` означает native
bridge, а не доказательство того, что нажимал человек: сравнивайте с UI-аудитом.

Безопасное чтение журнала:

```sh
source tools/android-env.sh
adb -d logcat -d -s QueueAudit:I '*:S'
python3 -m unittest discover -s tools -p 'test_device_ui.py'
```
