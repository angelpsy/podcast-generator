# Этап 2: постоянный фоновый плеер

Дата: 25 октября 2026 года, Asia/Tbilisi. Pixel 10 Pro / Android 17, USB к MacBook. Промежуточная версия **1.4 / versionCode 5**, тот же application ID и ключ подписи. **Этап 2 завершён:** длительный фон, холодное восстановление и временная потеря аудиофокуса проверены. Оставшиеся границы перечислены в конце; это не приёмка всех будущих этапов v2.

## Реализация

`PlaybackService : MediaSessionService` владеет единственными ExoPlayer и MediaSession. `PlaybackModule` подключается через MediaController; RN получает отдельные короткие snapshots без сценариев и токенов. UI-контроллер отключается при уходе в фон, не вызывая Pause; сервис сохраняет playback lifecycle. Смена выбранной карточки, настроек и запуск генерации не заменяют активную очередь. Выход UI больше не владеет Player.

Реализованы:

- Независимые от Activity прослушивание, audio focus, becoming-noisy и локальный wake lock во время воспроизведения.
- Мини-плеер на обоих существующих экранах, отдельный экран плеера со списком очереди.
- Play/Pause, seek к секунде, ±15 секунд, previous/next, 0,75–2× и repeat off/one/all.
- «Слушать выпуск»: продолжить текущий выпуск либо загрузить одиночную очередь. «Слушать библиотеку»: новый снимок всех READY-записей в порядке библиотеки, до 1000 элементов. Обычный поиск списка не меняет очередь.
- Системная MediaStyle notification, metadata и lock-screen/media-button управление.
- Сохранение очереди, текущего ID, позиции, скорости и repeat в Room; восстановление на паузе без автоматического звука. Позиция сохраняется по событиям и примерно каждые пять секунд.
- Подтверждённое удаление сначала убирает ID из активной очереди через session command с ответом; затем библиотека удаляет файл и запись.
- Недоступные ID/подтверждённо отсутствующие файлы пропускаются. Ошибка декодирования удаляет плохой элемент из многозаписной очереди, не создавая repeat-цикл. Для единственной записи ошибка оставляет URI для явного P-03 retry после восстановления файла.

Сервис принимает от приложения только library IDs: даже переданный клиентом URI заменяется URI из Room. Внешние controllers получают транспортные команды без изменения очереди, удаления и генерации. Системное возобновление читает только сохранённые ID. Разрешения manifest: FOREGROUND_SERVICE, FOREGROUND_SERVICE_MEDIA_PLAYBACK, WAKE_LOCK; тип сервиса mediaPlayback. Дополнительные разрешения на аудиотеку не требуются для собственных записей.

Архитектурная основа: [MediaSessionService](https://developer.android.com/media/media3/session/background-playback), [MediaController](https://developer.android.com/media/media3/session/connect-to-media-app). Media3 закреплён на 1.11.1; RN/Kotlin/Gradle и SIWC-протокол не обновлялись. Экспериментальный stageZero-плеер получил отдельный session ID, чтобы не конфликтовать с продуктовой сессией при совместной загрузке. compileStageZeroKotlin прошёл; его прежние device-пробы повторно не запускались.

## Room 1 → 2

Добавлена только таблица `playback_state(id INTEGER PRIMARY KEY, snapshot TEXT NOT NULL)` с единственной строкой. Snapshot содержит упорядоченные библиотечные IDs и настройки воспроизведения; URI, текст и OAuth туда не копируются. Существующие podcasts/audio_assets/generation_jobs/migration_state сохранены.

Миграция `PodcastDatabases.MIGRATION_1_2` зарегистрирована в общем экземпляре базы для библиотеки и сервиса; destructive fallback отсутствует. Экспортирована схема 2, схема 1 оставлена для проверки обновления. Тест создаёт настоящую SQLite v1 из экспортированного JSON, добавляет выпуск, asset, draft и legacy marker, открывает Room 2, проверяет строки, сохраняет playback и повторно открывает базу.

Если чтение сохранённой очереди не удалось, периодическое сохранение не заменяет её пустым состоянием. Некорректный snapshot остаётся для диагностики; пользователь может явно загрузить новую очередь из библиотеки. Отсутствующие элементы и неизвестный provider разделены: null query — ошибка, а не подтверждение удаления.

- **14/14** изолированных Room library-checks прошли на схеме 2.

- **10/10** проверок настоящего сервиса прошли **дважды подряд**: миграция, разрешение ID с намеренно неверным клиентским URI, сохранение pause/seek/speed/repeat, previous/next, автоматический переход, отсутствующий ID, реальная ошибка декодера, P-03 после замены содержимого того же URI, acknowledged removal, сохранность исходной библиотеки.

Финальный расширенный прогон прошёл **11/11**: к прежним десяти добавлен transient audio focus через Activity отдельного test APK/UID. Actor запрашивает AUDIOFOCUS_GAIN_TRANSIENT без звука, автоматически закрывается через 2,5 с и возвращает фокус. Наблюдались suppression/остановка и автоматическое продолжение. Activity отсутствует в release APK. В финальном runner ожидание старта дополнительно проверяет фактический ID и индекс, а сохранённые настройки — текущий ID.

Всего **31 уникальная Android-проверка**: 11 сервисных, 14 библиотечных и 6 прежних регрессий; повторный отдельный прогон миграции не считается ещё одним сценарием.

Декодерный тест публикует собственный временный M4A с неверными байтами и отдельной Room-записью. После проверки данные того же URI заменяются копией валидного M4A; повтор идёт через реальный MediaController. Fixture затем убирается из очереди и удаляется. Генерация OpenAI и чтение SIWC-токенов не выполняются.

Первый полный прогон остановился на `Timeout: next` после 3/10. После добавления безопасной диагностики состояния оба повторных прогона прошли; первоначальная причина без снимка состояния не установлена. Это не выдаётся за исправленную продуктовую ошибку. ## Повторить

На Mac, из корня проекта:

```sh
source tools/android-env.sh
cd mobile
npm run typecheck
npm run lint
npm test -- --runInBand
cd android
./gradlew :app:testReleaseUnitTest :app:lintRelease :app:assembleRelease :app:assembleReleaseAndroidTest -PplaybackChecks=true
adb install -r app/build/outputs/apk/release/app-release.apk
adb install -r app/build/outputs/apk/androidTest/release/app-release-androidTest.apk
adb shell am instrument -w dev.podcast.siwcspike.test/dev.podcast.siwcspike.podcast.PlaybackDeviceChecks
```

Полный runner требует разблокированный Pixel и хотя бы два готовых выпуска. Изолированная миграция доступна без UI:

```sh
adb shell am instrument -w -e migrationOnly true dev.podcast.siwcspike.test/dev.podcast.siwcspike.podcast.PlaybackDeviceChecks
```

Для 14 library-checks собрать и установить test APK с `-PlibraryChecks=true`; для 6 прежних — без обоих флагов. Компоненты: LibraryDeviceChecks и PodcastDeviceChecks соответственно. Как и на этапе 1, прежние шесть требуют сохранённого legacy журнала/файла; новые сервисные тесты используют текущую Room-библиотеку.

Ручной проход: выбрать «Слушать библиотеку» → открыть плеер → seek/±15/скорость/повтор → открыть настройки и вернуться → Home/recents dismissal → заблокировать → системные Pause/Play → не менее 15 минут очереди → разблокировать → pause и холодный запуск. Для Force stop сначала дождаться сохранения позиции (pause либо пять секунд), затем `adb shell am force-stop dev.podcast.siwcspike` и явный запуск MainActivity. Ожидается восстановленная очередь на паузе, без автозвука и повторного входа в SIWC.

## Границы

Плейлисты и структура топиков относятся к следующим этапам; «Слушать библиотеку» пока использует весь READY-каталог, а не поиск. В очередь нельзя пока перейти нажатием по её строке или вручную менять порядок. UI имеет базовый seek к секунде и ±15, без slider. Базовый generation runner остаётся foreground-only; его отмена независима от плеера.

Физическое отключение гарнитуры, постоянная потеря audio focus, reboot, Battery Saver/deep Doze, отказ уведомлений и одновременные длинные TTS/кодирование с playback ещё не проверены этим протоколом. Временная потеря audio focus проверена отдельным test APK. Becoming-noisy подключён штатным API ExoPlayer; это не заменяет проверку физического отключения гарнитуры.
