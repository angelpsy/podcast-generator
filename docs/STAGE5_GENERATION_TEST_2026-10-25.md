# Этап 5: языковые профили и очередь генерации

Дата: 25 октября 2026, Asia/Tbilisi. Android **1.7 / versionCode 8**, Pixel 10 Pro / Android 17. Обновление поверх 1.6 без очистки данных, смены подписи или новой SIWC-регистрации.

## Реализация

Добавлены `ru_standard`, `ru_simple`, `en_simple_ste`. Профиль связывает инструкцию, локальную проверку языка и TTS: русский/простой русский → ru, простой английский → en. Английский prompt ориентируется на короткие предложения, отсутствие идиом, единообразные термины и определения. Это профиль по мотивам ASD-STE100 с эвристикой длинных предложений; численное соответствие «80%» стандарту не измеряется и не заявляется.

ContentSettings: независимые volume, immersion, intent и audience. Четыре быстрые настройки: BRIEF 150–250 / OVERVIEW, STANDARD 350–550 / EXPLANATORY, DETAILED 700–1100 / EXPLANATORY (default), DEEP 1200–1800 / DEEP. В расширенном редакторе объём и погружение меняются отдельно. Нет обязательного перечня «ошибки/примеры/причины» и фиксированного числа смысловых блоков. Объём — ориентир, без растягивания текста, обрезки речи или автоматического нового запроса ради диапазона.

Язык и ContentSettings сохраняются в топике как defaults. Смена defaults не переписывает готовые файлы и настройки поставленных заданий. В отдельном выпуске и пакете они переопределяются; в предпросмотре пакета можно настроить каждый выпуск, затем пересчитать состав. Старые выпуски и черновики сохраняют прежнюю политику.

На вопросе доступно «Создать подкаст», на корне/разделе — «Создать обзор» или «Создать по вопросам». Обзор — один выпуск с дочерними темами в контексте, пакет — только конечные вопросы выбранной ветки. Отдельный выпуск из библиотеки не требует топика. Перед запуском показываются конкретные названия, язык/настройки, пропущенные готовые и активные задания, остаток за пределом лимита 20. Готовность проверяется по MAIN выбранного профиля, дополнительные версии создаются только явно. Один профиль вопроса не ставится повторно, пока его задание незавершено; FAILED требует явного повтора или удаления из очереди. requestId делает повторную отправку одного пакета идемпотентной.

Производный плейлист использует текущий профиль топика. Связи других профилей не удаляются: отдельный выпуск можно открыть из структуры. Прикрепление существующих записей поддерживает все три профиля. MAIN отдельный для каждого профиля; дополнительные версии становятся EXTRA. Если прежний MAIN потерял файл, новый готовый результат становится MAIN, прежняя запись сохраняется как EXTRA; следующий пакет уже пропускает готовый основной выпуск.

## Сценарий и SIWC

`EpisodeScriptV1`: title, summary, segments[{heading,text}], tags. Используется Responses/SSE, store:false, строгая text.format JSON Schema; [официальный формат Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses). Отказы и незавершённый поток остаются ошибками. Выбранная модель не подменяется. Сетевая операция Responses получает ограниченный call budget 240 с; auth и остальные операции сохраняют прежние бюджеты. Для будущего ожидания результата есть отдельный предел 300 с.

Локальная проверка ограничивает JSON 32 768 code points / 128 KiB, сегменты 1–24, всю произносимую речь — 3000/6500/12000/20000 code points по выбранному объёму. Отбрасываются непроизносимая разметка и грубое несоответствие языка; русская речь допускает английские технические названия. Метаданные/heading/tags не озвучиваются. Неверные необязательные теги отбрасываются, до восьми корректных сохраняются.

До TTS в Room записываются нормализованный сценарий, SHA-256, фактическая модель, promptVersion, настройки, фактическое число слов и qualityWarnings. Метод words-v1 считает последовательности букв/цифр, дефисные слова и апострофы как одно слово; десятичная запись с точкой/запятой внутри числа не разбивается. Отклонение от диапазона более примерно 20% и английское предложение длиннее 25 слов — предупреждения, без скрытого повторного запроса. Эвристики не оценивают достоверность рассказа или формальное соответствие STE.

## Хранение и восстановление

Room **5**, явная миграция **4 → 5**, полная цепочка 1 → 2 → 3 → 4 → 5, без destructive fallback. Topic получает languagePolicy и contentSettings. `generation_queue` хранит ID, batchId, исходный title, topic/node IDs, профиль, копию настроек и контекста, fingerprint источника, выбранную модель, status, phase, безопасную ошибку, createdAt и attempt. FK на topic/node намеренно отсутствует: удаление структуры не уничтожает задание или результат.

Один процессный PodcastCoordinator и один serial worker выполняют SIWC и TTS последовательно. Короткие preview/enqueue/cancel операции имеют отдельный DB-worker, поэтому они не ждут завершения длинной озвучки. Атомарный claim QUEUED → RUNNING не запускает уже отменённое задание. Переключение вкладки не отменяет генерацию. Пауза/блокировка/уход в фон останавливает текущую операцию и ставит оставшиеся задания на PAUSED. После смерти процесса RUNNING/QUEUED восстанавливаются на паузе, без автоматического Responses. Продолжение — всей очереди либо выбранного выпуска, повтор FAILED — явный. Для задания без сохранённого сценария UI предупреждает о новом запросе. Сетевая локальная идемпотентность не гарантирует exactly-once на стороне сервиса при обрыве до сохранения terminal response.

Рабочие данные: `noBackupFilesDir/podcast/jobs/<id>/`. Каждый законченный TTS-фрагмент — отдельный PCM16 mono WAV, записанный через `.part` и rename. AtomicFile manifest фиксирует идентичность сценария/языка/голоса/параметров, rate, frames и hash каждого фрагмента. При продолжении проверяются header/размер/hash; незавершённый `.part` не используется. Полный WAV собирается последовательно с буфером 64 KiB, без PCM-массива всего выпуска. M4A проходит прежнюю инспекцию и протокол MediaStore.

Дисковый резерв учитывает фрагменты, сборку, кодирование/публикацию и запас; вычисляется консервативно по верхнему бюджету выбранного объёма. До TTS используется оценка max(words×0.9, codePoints×0.18) секунд × 44 100 × 2 × 3 плюс 64 MiB. Это оценка ресурса, не обещанная длина речи. Локальный этап ограничен 20 минутами и отдельным 120-секундным watchdog текущего фрагмента; отмена JNI кооперативная.

READY библиотеки, статус COMPLETED очереди и актуальная связь с узлом фиксируются в транзакции публикационного журнала. Если процесс оборвался вокруг публикации, прежний протокол сверяет MediaStore перед новой генерацией. Не появляются второй файл или повторная связь с тем же ID. Если исходный контекст изменён/удалён или достигнут лимит связей, готовый выпуск остаётся самостоятельным, с attachmentWarning в метаданных и сообщением в карточке. Исходные ID/путь/названия/описания/тип узла входят в fingerprint; изменение одних defaults не меняет контекст. Активная очередь воспроизведения — независимый снимок IDs.

- Реальный пакет: простой русский / BRIEF + DEEP, простой английский / BRIEF + OVERVIEW. Русский сценарий и один законченный фрагмент сохранены до паузы. - Подробный самостоятельный RU / DETAILED + OVERVIEW тем же runner: 934 слова, 20 фрагментов, 561 190 мс (9:21). Полный live-прогон PASS 13/13. Смена вкладки во время синтеза не останавливает его. Во время TTS существующий плеер давал PLAYING/foreground, позиция росла с 3,7 до 6,7 с (effective около 4,4 → 9,0); это короткая совместная проверка, не повтор длительного теста этапа 2.

## Проверка обычного UI и редактора очереди

В редакторе топика сохранены en_simple_ste, BRIEF + DEEP. Готовые файлы не изменились: английский плейлист показал ровно английский вопрос, русский остался в структуре. Пакетный preview показал один новый EN и один пропущенный готовый EN. Для единственного нового выпуска выбран ru_simple, после пересчёта получено ноль новых и два пропущенных готовых; отправка отключена, новых файлов не создано. SINGLE preview корня показал ровно один обзор с defaults топика. Отдельный выпуск из библиотеки открылся с независимыми ru_standard / DETAILED defaults.

На итоговом runner дополнительно выполнена настоящая озвучка копии уже сохранённого сценария, без нового Responses. Во время синтеза preview и enqueue ответили в пределах пяти секунд, ожидающее задание было отменено и не могло пройти claim. Текущая озвучка поставлена на паузу; тестовые task IDs/черновик удалены, исходные READY journals совпали. SIWC operationId не менялся. Это отдельный сценарий GenerationDeviceChecks с `-e runner true` и временными данными, не четвёртый сохранённый подкаст.

Английская запись запущена из плейлиста: PLAYING, одна запись в очереди, затем естественный конец около 102,6 с. Пользователь подтвердил прослушивание английского образца: «Да, речь понятна, проблем нет». Для этой записи подтверждены понятность и отсутствие заметных обрывов/повторов; это не оценка всей матрицы языков и настроек.

## Ошибки подготовки тестов

JVM не предоставляет настоящий Android AtomicFile. Для файлового алгоритма SpeechCheckpoint внедрён AudioJournal factory, в unit-тестах используется файловая реализация; production по умолчанию использует прежний AtomicAudioJournal. На Pixel отдельно проверен настоящий AtomicFile. Ещё два теста уточнили поведение контракта: неверные необязательные теги отбрасываются строгим JSON reader с проверкой типов, а превышение лимита всей речи возвращает answer_too_large.

Первый live-прогон подтвердил паузу, затем тест слишком рано проверил асинхронный resume и увидел прежний PAUSED. Добавлено ожидание принятой команды. Повтор использовал тот же топик, те же task IDs, сохранённый сценарий и фрагмент — новая копия первого запроса не создавалась.

Без live тестируются временные изолированные базы, удаляемые в finally. `-e runner true` проверяет отзывчивость preview/enqueue/cancel во время TTS уже сохранённого ru_simple-сценария, без новой сети; нужны готовый ru_simple выпуск и разблокированное приложение. `-e live true` перед component дополнительно использует реальную SIWC-сессию и лимиты подписки, оставляет топик и M4A для проверки. Pixel должен оставаться разблокированным; не очищать данные приложения. После прерывания теста сохранённые задания можно продолжить через UI, без нового запроса уже сохранённого текста.

Прежний TopicDeviceChecks из этапа 3 выбирал любые две последние записи и ожидал их обе в русском плейлисте. С появлением EN это ожидание перестало соответствовать правилам. Для теста сохранности очереди теперь выбираются две RU-записи; отдельные новые проверки подтверждают фильтрацию RU/EN.

## Границы

Генерация в фоне — следующий необязательный этап; фоновое прослушивание сохранено. История завершённых заданий и отдельный thermal-monitor UI не добавлены. Generic сбои сети/auth/ресурсов ставят очередь на паузу; ошибки содержимого не повторяются скрыто. Полная матрица трёх профилей × четырёх presets × разных областей, физический OOM/перегрев и длительный параллельный playback относятся к отдельной расширенной приёмке. Синтаксическая проверка и числа слов не заменяют человеческую оценку понятности и смысловой точности.
