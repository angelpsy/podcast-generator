# Pixel: полный сценарий создания подкаста

Дата: 25 октября 2026 года, Asia/Tbilisi (UTC+4). Устройство: Pixel 10 Pro, Android 17, arm64-v8a. Сборка установлена по USB поверх предыдущей, без очистки данных и повторного OAuth-входа.

## Проверяемая версия

- Android versionName `1.2`, versionCode `3`.
- Финальный release APK: `mobile/android/app/build/outputs/apk/release/app-release.apk`, 183 215 518 байт (около 174.7 MiB).
- SHA-256: `668b18adb3107ba51a4b0447bfd0eda3ff690c7deb428229a7e781ef37400b0a`.
- Подпись APK и `zipalign -c -P 16 4` проверены. Телефон использует страницы 4 KiB; отдельной проверки на устройстве с 16 KiB нет.
- 43 JVM-теста: 18 прежних SIWC, 7 публикации/очистки, 2 WAV, 2 JNI callback, 7 Responses streaming, 7 подготовки текста/разбиения/повтора/приватности.
- TypeScript, ESLint, Jest (1 тест приватности) пройдены. Android lint: 0 ошибок, 23 предупреждения.
- SIWC: общий Kotlin-клиент, account-specific каталог, Responses API. TTS: Supertonic 3 INT8 / sherpa-onnx 2.0.0, CPU, 2 потока, 8 шагов, sid 0, ru. Кодирование: Media3 Transformer 1.11.1, AAC-LC mono 44 100 Hz, целевой битрейт 96 kbit/s.

## Первый полный выпуск

Тестовая тема: `Why is the sea salty?`. Английский ввод выбран намеренно, чтобы проверить русский язык результата. Использована первая видимая модель текущего каталога — `gpt-6.1-sol`; модель не зашита в код приложения.

При первом запуске в 02:18 приложение обнаружило необходимость refresh: discovery, token exchange, JWKS и models завершились с HTTP 200. Прежняя регистрация/подписка сохранились. API key не вводился, новый OAuth-вход не выполнялся.

Первая попытка выявила ошибку обработки завершения SSE, исправленную до успешной проверки: [P-01 в журнале](SIWC_ERROR_LOG.md#p-01--завершающее-sse-событие-не-повторяет-уже-полученный-текст). Предыдущая запись при ошибке осталась. После обновления APK восстановилась введённая тема.

Успешный проход: 02:21:38 → 02:22:35. Он выполнен на APK `6818341084518211cbef5ebe50fa90d7623c9b53050ec92de159c94057a380e4` (183 215 426 байт). Финальная сборка дополнительно уточняет статус восстановленного черновика и доступность кнопки продолжения при загрузке каталога; её проверка описана ниже. В потоке получено 1010 code points, после нормализации пробелов — **1006 символов, 158 слов**, русский связный рассказ о солёности моря. `response.completed` получен; `final_text_parts=0`, поэтому использован завершённый поток deltas. ## Восстановление текста после остановки

Вторая попытка по той же теме начата в 02:24:37. В 02:24:48 получен завершённый ответ (969 code points), текст записан в приватный черновик, затем начался первый фрагмент TTS. После появления `Synthesizing` приложение свёрнуто через Home: lifecycle запросил отмену. До принудительной остановки процесса завершение native-отмены не было подтверждено в логе; это не замер её задержки.

Во время незавершённой озвучки выполнены `am force-stop` и холодный запуск, затем обновление до финального APK без очистки данных. Исходный M4A остался единственным файлом, его SHA-256 совпал с исходным. Тема и готовый текст черновика восстановились. Финальный UI показывает «Есть незавершённый подкаст» и доступную кнопку продолжения даже во время загрузки каталога, если завершённый текст уже сохранён.

В 02:27:38 нажато «Продолжить с сохранённого этапа». Последовательность: PreparingVoice → Synthesizing (три фрагмента) → Encoding → Saving → Ready. Этап GeneratingText отсутствовал. В безопасном logcat после запуска финального APK — **0 запросов Responses**, один GET models для интерфейса, три этапа фрагментов и одно завершение публикации. Повтор текста не выполнялся.

## Внешний плеер и подтверждение пользователя

Из приложения нажато «Открыть в другом приложении», в системном chooser выбран AIMP. Android MediaSession показала `package=com.aimp.player`, `PLAYING`, имя `podcast-1792880677467-78aee4fa`, без ошибки. Широкие разрешения на библиотеку телефона в этом тесте не выдавались; использован content URI с временным правом чтения.

Пользователь подтвердил: **«Да, рассказ слышен и понятен»** в ответ на вопрос о связной русской речи без заметных обрывов или повторов. Это субъективная проверка данного рассказа/голоса, а не гарантия произношения любых тем.

Mac `afinfo`: одна дорожка AAC mono 44 100 Hz, 96 000 bit/s, 75.440 с. `afconvert` полностью декодировал итоговый файл в PCM16. В M4A остаётся служебное место muxer, поэтому размер контейнера выше, чем размер AAC payload; это ранее отмеченное ограничение минимального прототипа.

## Границы проверки

Это минимальный рассказ одним голосом, без исследования источников, редактора текста, истории выпусков и фонового сервиса. Тема и завершённый текст хранятся приватно в `noBackupFilesDir`; наружу публикуется только аудиофайл. Диагностика исключает тему, текст, email, URI и OAuth-данные.

Целевые 120–180 слов задаются инструкцией; жёсткий предел — 3000 Unicode code points. Длительность аудио не фиксирована. Отказ, пустой ответ, overflow, incomplete, EOF и отмена проверены JVM-тестами; это не искусственно вызванные серверные ошибки на подписке пользователя.

Остановка внутри JNI остаётся кооперативной; native-синтез может закончить текущую работу прежде, чем вернётся управление. В предыдущем [тесте TTS](DEVICE_TTS_TEST_2026-10-25.md) отмена после сворачивания занимала около 27 секунд. Длительный термотест, произвольные темы/имена/ударения, физическая нехватка места и авиарежим в этом проходе не проверялись.
