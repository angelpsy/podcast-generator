# Подкасты v2 — продуктовая спецификация

Дата: 25 октября 2026 года, Asia/Tbilisi. **Статус: основные этапы 0–6 реализованы в 1.8; фоновое создание остаётся необязательным этапом 7.** База — коммит `ac1eaa7`, рабочий Android-прототип 1.2. Этот документ описывает продуктовые правила. [Техническая спецификация](PODCAST_V2_TECH_SPEC.md), [этапы с критериями приёмки](PODCAST_V2_PLAN.md), [SIWC/TTS/плеер](STAGE0_V2_TEST_2026-10-25.md) и [Room/навигация](STAGE0_COMPATIBILITY_TEST_2026-10-25.md) дополняют его.

## 1. Цель и подтверждённые требования

Превратить генератор одного рассказа в личную аудиобиблиотеку для изучения тем. Пользователь сначала составляет и редактирует структуру, затем по собственному выбору создаёт записи и слушает их последовательно, включая заблокированный экран.

Обязательно для v2:

- фоновое воспроизведение и системное управление аудио;
- отдельная генерация структуры топика через текущую подписку ChatGPT, без создания аудио;
- настраиваемая глубина дерева, ручное добавление, изменение, удаление, перестановка и перенос пунктов;
- один подкаст по любому уровню либо несколько подкастов по вопросам выбранной ветки;
- плейлист топика, воспроизведение отдельной ветки, общий список плейлистов и библиотека записей;
- отдельный подкаст без топика, поиск по названию и добавление существующей записи в топик или плейлист;
- русский, простой русский и простой английский с опорой на ASD-STE100;
- тёмная тема;
- удаление прежних тестовых экранов из пользовательского приложения.

Уточнения пользователя: фоновое **создание** желательно, если не требует большого усложнения, но не обязательно. Для каждого подкаста нужен выбор объёма и степени погружения; по умолчанию подробный рассказ, без точного хронометража. Темы включают техническое обучение, научпоп и другие области. Предлагаем четыре готовые настройки, но не фиксируем число смысловых блоков или обязательные «причины, примеры и типичные ошибки» для любого рассказа.

## 2. Организация: топик, подкаст и плейлист

| Сущность | Назначение | Что не происходит автоматически |
| --- | --- | --- |
| Топик | Название, цель, профиль языка, дерево разделов и вопросов | Создание структуры не запускает генерацию выпусков |
| Раздел / вопрос | Узел дерева с названием, описанием и порядком | Изменение названия не перезаписывает готовый звук |
| Подкаст | Самостоятельная запись: сценарий, язык, подробность, M4A, прогресс прослушивания | Удаление связи с топиком не удаляет запись |
| Плейлист топика | Представление готовых записей в порядке дерева | Изменение структуры не перестраивает уже запущенную очередь без действия пользователя |
| Пользовательский плейлист | Ручная подборка любых записей в своём порядке | Аудиофайлы не копируются при добавлении |
| Очередь воспроизведения | Список конкретных записей, выбранных для текущего прослушивания | Новая генерация не вставляет звук в проигрываемую очередь неожиданно |
| Очередь создания | Сохранённый список заданий на текст и озвучку | Не выполняет заново успешно завершённые задания |

В интерфейсе используем термин **«Топик»**, вложенные элементы — «Раздел» и «Вопрос». Отдельную сущность «Модуль» не вводим: это ещё одно название раздела с теми же свойствами.

Пример структуры, глубина 3 ниже топика:

```text
Подготовка к интервью
  Сети
    Клиент-серверное взаимодействие
      Как проходит HTTP-запрос?
      Чем отличаются REST и RPC?
  JavaScript
    Как работают замыкания?
    Как устроен event loop?
```

Подкаст «Как работают замыкания?» может одновременно находиться в этом топике и в ручном плейлисте «Повторить перед собеседованием». Это один файл и одна запись библиотеки.

## 3. Основные экраны

Три нижние вкладки: **Топики · Подкасты · Плейлисты**. В верхней части доступны настройки и очередь создания с количеством незавершённых заданий. Над вкладками — компактный плеер текущей записи. Полный плеер открывается нажатием на него.

| Экран | Основные действия |
| --- | --- |
| Топики | Создать топик, открыть структуру, увидеть число готовых вопросов |
| Создание топика | Ввести тему и цель, выбрать язык, глубину, ориентир количества пунктов; создать структуру или начать вручную |
| Топик | Переключить «Структура / Слушать», редактировать дерево, создавать или прикреплять записи |
| Раздел / вопрос | Изменить описание, посмотреть привязанные записи, создать обзор или выпуски по вопросам |
| Предпросмотр структуры | Проверить предложенные пункты, исправить их, применить или отклонить |
| Подкасты | Все записи; поиск по названию; фильтры языка, готовности и прослушанности; создать отдельный выпуск |
| Подкаст | Название, профиль, подробность, текст, воспроизведение, добавить в топик/плейлист, открыть внешним плеером, удалить |
| Плейлисты | Автоматические плейлисты топиков и пользовательские подборки с явной отметкой типа |
| Плейлист | Прослушать с начала / продолжить, посмотреть записи, редактировать ручную подборку |
| Очередь создания | Текущий этап, готово N из M, пауза, продолжить, отменить, повторить конкретную ошибку |
| Настройки | ChatGPT: подключение/выход; модель из каталога; язык и подробность по умолчанию; оформление; место на диске; версия и лицензии |

Все экраны библиотеки доступны без входа и без сети. Вход требуется для нового запроса к OpenAI. Уже сохранённый сценарий можно озвучить без сети.

## 4. Структура топика

### Глубина и объём

Глубина — максимальное число уровней **ниже корня топика**. Предлагаем диапазон 1–4, по умолчанию 2: «Топик → раздел → вопрос». На форме показываем маленький пример выбранного варианта. Уменьшение настройки не обрезает существующее дерево; настройка применяется к следующим предложениям модели.

Количество пунктов отделено от глубины: первоначальный ориентир 3–5 на разворачиваемый раздел. Для большой темы сначала генерируем верхние уровни; пользователь может отдельно раскрыть нужную ветку. Предлагаемые ограничения v2: до 50 новых узлов за запрос и до 200 узлов в топике. Это границы объёма работы, а не требование заполнить все уровни и ветки.

### Создание и редактирование

1. Пользователь задаёт название/вопрос, при желании цель и уровень подготовки.
2. Выбирает профиль языка и глубину. Нажимает **«Создать структуру»**.
3. Модель возвращает разделы и вопросы. Появляется отдельный предпросмотр, аудио отсутствует.
4. Пользователь применяет предложение; затем может редактировать каждый пункт вручную.

Ручные действия: добавить раздел или вопрос; изменить название/описание; переместить вверх/вниз; перенести в другой раздел того же топика; удалить ветку. Перетаскивание можно добавить позднее: в первой версии все операции доступны через меню, в том числе с TalkBack. Вопрос не содержит дочерних узлов; действие «Разбить на подразделы» превращает его в раздел с сохранением его ID и привязанных записей.

Для существующей ветки модель предлагает **добавления** или отдельный **вариант замены**. Изменение показывается до применения. Ручные правки и существующие связи не исчезают от ответа модели. Если дерево изменилось во время запроса, предложение требует повторного просмотра; автоматического слияния нет.

При удалении ветки показываем число вложенных пунктов и связей. Аудио остаётся в библиотеке. При удалении топика также удаляется его автоматический плейлист, но не сами записи.

## 5. Создание подкастов

На корне и любом разделе:

- **«Создать обзор»** — один рассказ по выбранному узлу, с учётом цели топика и дочерних тем;
- **«Создать по вопросам»** — отдельные выпуски по конечным вопросам выбранной ветки. По умолчанию только те, у которых ещё нет основного выпуска выбранного профиля;
- **«Добавить готовый подкаст»** — поиск в общей библиотеке и создание связи.

На вопросе — **«Создать подкаст»** и добавление готового. Пустой раздел может получить обзор, но не запускает пустой пакет. Генерация по всем уровням одновременно не является действием по умолчанию: это породило бы повторяющийся контент.

Перед пакетным запуском показываем конкретные вопросы, число новых записей, пропущенные готовые/уже поставленные задания, язык и подробность. Настройки пакета можно поменять для отдельных элементов. Один запуск ставит не более 20 новых заданий; большой топик создаётся частями. Значения — предлагаемая конфигурация v2, не лимит сервиса OpenAI.

Отдельный выпуск создаётся из вкладки «Подкасты», не требует топика и сразу появляется в библиотеке. Потом его можно добавить в любой топик или ручной плейлист.

### Объём, погружение и цель рассказа

Разделяем три независимых свойства:

- **Объём:** примерно сколько слов будет в произносимом тексте. Это ориентир размера, а не обязательство растянуть ответ.
- **Погружение:** сколько контекста, взаимосвязей и существенных нюансов объяснить внутри выбранного объёма.
- **Цель:** что пользователь хочет получить от рассказа. Она задаётся темой и необязательным полем «Что хочется узнать / на чём сделать акцент?».

Для быстрого создания достаточно одного выбора готовой настройки. В «Настроить» объём и погружение можно менять отдельно:

| Готовая настройка | Ориентир объёма | Погружение по умолчанию |
| --- | --- | --- |
| Кратко | 150–250 слов | Обзорное: основная идея, минимальный необходимый контекст |
| Стандартно | 350–550 слов | Объясняющее: связное раскрытие основных аспектов |
| **Подробно — по умолчанию** | 700–1100 слов | Объясняющее: больше контекста, связей и уместных деталей |
| Углублённо | 1200–1800 слов | Глубокое: существенные нюансы, границы объяснения и альтернативные взгляды, когда они уместны |

В расширенной настройке объём выбирается из этих четырёх диапазонов, погружение — обзорное / объясняющее / глубокое. Например, длинный вводный рассказ и короткий разбор узкого нюанса — допустимые разные сочетания. При небольшом объёме и глубоком погружении сужаем охват до главного вопроса, а не ускоряем речь и не набиваем текст терминами. Если сама тема слишком узкая, не добавляем повторы ради нижней границы слов.

Цель и настройки наследуются от топика, могут переопределяться для пакета и отдельного выпуска и сохраняются вместе с заданием. Уровень подготовки слушателя задаётся отдельно от простоты языка. Подробный научпоп для новичка и подробный технический разбор для опытного специалиста не получают один шаблон содержания.

**Структура рассказа адаптируется к запросу.** Не требуются фиксированные 3–5 блоков, обязательный пример, список ошибок или сравнение подходов. Пользователь не обязан выбирать жанр из каталога: по умолчанию достаточно темы, цели и аудитории. Указанное пожелание пользователя важнее автоматически выбранной подачи.

| Запрос / цель | Возможная организация подробного рассказа |
| --- | --- |
| «Замыкания в JavaScript; подготовиться к интервью» | Механизм, связь с областью видимости, уместные примеры, нюансы, которые полезны на интервью |
| «Как учёные узнали, из чего состоят звёзды; хочу научпоп» | Исследовательский вопрос, наблюдения и открытия, объяснение метода, что удалось установить и что остаётся неизвестным |
| «История города; понять, как он менялся» | Хронология, поворотные события, жизнь людей и контекст эпох |

Это иллюстрации адаптации, не новые обязательные шаблоны. Для научных тем нельзя придумывать эксперименты, цитаты или уверенность там, где есть неопределённость. Наличие длинного рассказа само по себе не означает проверку внешних источников: исследовательский поиск остаётся вне базовой v2.

Диапазоны слов — предварительные продуктовые ориентиры, уточняемые по качеству и замерам Pixel. Фактическое число слов и длительность доступны после создания. Количество разделов дерева топика, число внутренних фрагментов TTS, объём и погружение не связаны один-к-одному. Языковой профиль управляет формулировками: глубокий рассказ также может быть на простом русском.

Повтор неудачной озвучки использует сохранённый сценарий. Действие **«Создать новую версию»** явно получает новый текст и запись; прежняя остаётся в библиотеке. После успеха новая версия становится основной в выбранном узле, но ручные плейлисты с прежней версией не изменяются.

## 6. Плейлисты и режим прослушивания

У каждого топика есть один автоматический плейлист. В режиме «Слушать» видны готовые записи, группировка по разделам и пропуски ещё не созданных вопросов. Неготовые элементы не превращаются в «тишину» и не запускают генерацию при воспроизведении.

Порядок: обзор узла, дополнительные записи этого узла, затем дочерние узлы сверху вниз. Для основного выпуска учитывается выбранный языковой профиль. Один и тот же podcast ID при обходе ветки воспроизводится один раз, по первому вхождению. Корень топика может иметь собственный обзор. Кнопка «Слушать раздел» создаёт очередь только для выбранной ветки.

По умолчанию языковой фильтр плейлиста соответствует профилю топика; доступно «Все профили». При добавлении записи другого профиля это явно видно. Профиль не подменяется молча при отсутствии нужного выпуска.

Автоматический плейлист следует дереву. Для произвольной перестановки предусмотрено **«Скопировать в свой плейлист»**; копируются ссылки, не файлы. В ручном плейлисте записи добавляются, удаляются и переставляются независимо от топиков. Повторное добавление того же podcast ID не создаёт дубль.

При запуске прослушивания фиксируется текущий список. Изменение топика, фильтра или создание новой записи влияет на следующий запуск; для немедленного изменения — явное «Обновить очередь». Уже играющий трек не обрывается от переименования или перестановки разделов.

Плеер: play/pause, предыдущая/следующая запись, перемотка, ±15 секунд, скорость 0,75–2×, очередь, повтор выключен/запись/плейлист. В учебных топиках порядок последовательный; shuffle не обязателен для v2. Позиция и текущая запись сохраняются. После перезапуска доступно «Продолжить», без неожиданного автозапуска.

Прослушивание продолжается при Home, блокировке и выключении экрана; работает управление с экрана блокировки и гарнитуры. Отключение наушников ставит паузу. Принудительная остановка приложения средствами Android останавливает и сервис; обещания работы после Force stop нет.

## 7. Языковые профили

| UI | Внутренний профиль | Правила |
| --- | --- | --- |
| Русский | `ru_standard` | Естественная взрослая речь, точные технические термины, объяснение новых понятий |
| Простой русский | `ru_simple` | Короткие предложения, одна мысль за раз, термин сначала объясняется, конкретные примеры; без детского тона и потери содержания |
| English — simple | `en_simple_ste` | Простой английский с опорой на принципы ASD-STE100: последовательные термины, короткие фразы, минимум идиом и неоднозначности |

Обычного и сложного английского в настройках нет. Профиль топика применяется к генерируемым названиям/описаниям структуры и по умолчанию к будущим подкастам. При создании отдельного выпуска или пакета профиль можно переопределить. Смена настройки топика не переводит существующие пункты и не перезаписывает звук; перевод существующей структуры — отдельное будущее действие.

Запрос «примерно 80% ASD-STE100» понимаем как практическую близость к правилам простого технического английского, а не как сертификацию или вычисленный процент. Для описательного текста стандарт использует, в частности, предел 25 слов в предложении и одну тему абзаца; в проекте добавляем конкретные проверяемые ориентиры и отдельную оценку качества. [ASD-STE100, Issue 9, раздел 6](https://www.asd-ste100.org/assets/files/ASD-STE100_ISSUE9.pdf). Полное соответствие словарю и всем правилам не заявляется.

Интерфейс v2 остаётся русским. Язык интерфейса и язык контента — разные настройки.

## 8. Поиск, теги и хранение

Поиск выполняется по названию всех записей, включая самостоятельные и связанные с топиками. Он нечувствителен к регистру; «ё» и «е» эквивалентны. В сценариях, описаниях и аудио поиск в v2 не выполняется. Дополнительные фильтры не расширяют скрыто область текстового поиска.

Предлагаем 0–5 редактируемых тегов на выпуск. Модель предлагает их в том же ответе, что и сценарий, без отдельного запроса; теги необязательны и не блокируют сохранение хорошего выпуска. В первом интерфейсе теги можно показать в карточке и использовать как явный фильтр. Семантический поиск и embeddings не нужны.

**Правило «оставлять только последний файл» заменяется библиотекой.** Все готовые выпуски сохраняются до явного удаления. M4A/AAC и открытие внешним плеером остаются. В настройках видны размер аудиотеки и временных файлов; можно убрать завершённые временные данные и выбранные записи.

Удаление записи требует подтверждения с количеством затронутых связей. При удалении из плейлиста или топика убирается только связь. Если файл удалён пользователем через файловый менеджер, карточка помечается как недоступная; запись не пересоздаётся за счёт подписки автоматически.

Облачная синхронизация и восстановление библиотеки после удаления приложения пока не входят. Публичные M4A не заменяют резервную копию структуры и связей; перед длительным накоплением большой библиотеки разумен отдельный этап экспорта/импорта.

## 9. Тёмная тема и очистка интерфейса

Оформление: «Как в системе» по умолчанию, «Тёмная», «Светлая». Темизируются навигация, поля ввода, диалоги, ошибки, мини-плеер, полный плеер и системные панели. Проверяются читаемость и крупный системный шрифт, состояния не различаются только цветом.

Из release-интерфейса удаляются экран SIWC Spike, произвольный тестовый запрос, ручной тест refresh, «Тест голоса», raw JSON/HTTP, PSS и времена внутренних этапов. Подключение ChatGPT, выбор модели, выход и понятное сообщение об ошибке остаются обычными настройками. Тесты и безопасные технические логи остаются в инструментах разработки, не в скрытом пользовательском тестовом меню.

## 10. Фоновое создание и границы v2

**Обязательно:** воспроизведение в фоне. **Базовый вариант создания:** очередь выполняется при открытом приложении, не зависит от выбранной вкладки и сохраняется на диск. При уходе в фон она ставится на паузу; завершённый текст и завершённые фрагменты озвучки не теряются. После возврата пользователь продолжает её. Прерывание сетевого ответа может потребовать нового запроса; это явно показывается.

Чтобы подробный выпуск не прерывался обычным тайм-аутом дисплея, предлагается удерживать экран включённым, пока пользователь видит приложение и очередь действительно работает. Пауза/завершение снимает это удержание. Ручная блокировка и Home всегда уважаются; фоновой работой это не считается.

**Необязательное расширение:** обработка очереди при заблокированном экране с постоянным уведомлением. Оно проходит отдельную техническую проверку после основных функций и не задерживает v2. Не выдаём foreground-only очередь за фоновую и не используем сервис плеера для скрытой генерации.

Откладываем: iOS, обычный английский, несколько дикторов, музыку, web-research и цитирование источников в самих подкастах, редактор аудио, автоматические расписания, облако, каталог альтернативных TTS, экспорт плейлистов для внешнего плеера. Индивидуальные M4A можно открывать снаружи; внутренний плейлист не считается автоматически перенесённым в AIMP.
