# Уточнение UX — Android 1.10

Дата: 25 октября 2026, Asia/Tbilisi. Версия 1.10 / versionCode 11, обновление поверх 1.9. Серая палитра и оранжевые акценты сохранены.

## Что изменено

- Play/Pause: круглая кнопка 48 × 48 dp в мини-плеере и 64 × 64 dp в полном плеере, одинаковые размеры для обоих состояний. Текстовая ширина символа больше не определяет форму кнопки.
- Оранжевый нижний бордер заменён настоящей шкалой: заполнение = позиция / длительность, с ограничением 0…100%. При неизвестной длительности — пустая шкала. Accessibility сообщает время и процент.
- «⋯» у топика, раздела и привязанной записи открывает модальное контекстное меню поверх экрана. Действия не добавляются в карточку. Закрытие — Android Back или касание вне меню; удаление сохраняет отдельное подтверждение.
- Под светло-серой кнопкой «Новый топик» расположена «Новый подкаст». Она переключает вкладку и открывает полную форму отдельного выпуска с пустой темой. Такая же форма используется кнопкой библиотеки.
- У каждого выпуска показаны текущие топики либо «Без топика». Читаются фактические связи Room, включая несколько топиков; несколько связей в разных узлах одного топика не дублируют название. Возврат во вкладку обновляет подписи. Сам выпуск в общем списке остаётся один.
- Внутри топика сразу под переключателем режимов видны «+ Раздел», «+ Вопрос», «+ Подкаст». Первые две формы заранее выбирают нужный тип. Последняя предлагает создать новый выпуск для текущей темы или прикрепить готовый. На конечном вопросе создание вложенных пунктов недоступно.
- Явная основная кнопка «Создать подкасты для всего топика» / «Создать подкасты для раздела» открывает выбор «Все разделы и вопросы» или «Только вопросы», затем предпросмотр количества и состава.
- «Создать обзор» заменено на «Один подкаст по теме» / «Один подкаст по разделу» с пояснением: один связный рассказ по всей выбранной теме. Для вопроса — «Создать подкаст по вопросу».

## Пакетное создание

Ранее BATCH выбирал только QUESTION. Теперь необязательный includeSections включает SECTION; старые запросы без флага сохраняют прежнее поведение. В UI нового пакета по умолчанию выбраны разделы и вопросы. ROOT в пакет не входит: один рассказ по всему топику запускается отдельной кнопкой. Внутри выбранного раздела могут создаваться выпуск самого раздела и выпуски его потомков.

Сохраняются DFS-порядок, проверка revision, языковой профиль, пропуск готовых основных/активных заданий, индивидуальные настройки, лимит 20 новых заданий за запуск и идемпотентный requestId. Изменение состава между просмотром и запуском отклоняется. Предпросмотр не создаёт задания, текст или аудио. После перехода к предпросмотру прокрутка возвращается к началу, где видны количество и первые пункты.

DAO добавляет проекцию фактических связей Podcast → Topic; таблицы и Room 6 не изменены, миграция не нужна. Старые записи без languagePolicy показываются как русский legacy-профиль.

## Автоматические проверки

- TypeScript и ESLint: без ошибок и предупреждений.
- Jest: 8 тестов / 4 набора. Новые проверки заполнения прогресса: начало/четверть/конец, выход за границы, неизвестная длительность и нечисловые значения.
- JVM: 112 тестов, без ошибок.
- GenerationDeviceChecks: 14/14, включая два новых сценария разделов/вопросов, DFS, исключение корня, scopes сценариев, защиту при смене выбора, создание пустого раздела, привязку и пропуск готовых/активных заданий.
- LibraryDeviceChecks: 15/15. Новый сценарий: два топика, несколько узлов одного топика, переименование, поиск, удаление и отвязка без удаления подкаста. Дополнена проверка языка старых записей.
- Android lint release: 0 ошибок, 25 прежних предупреждений.

## Проверка Pixel

Проверены меню поверх экрана и переход из него в редактирование, новая кнопка отдельного подкаста с пустым полем и недоступным запуском пустого запроса, актуальные подписи топиков у реальных записей. На существующем топике из 13 узлов предпросмотр всех разделов и вопросов показал 12 новых выпусков, с разделами и вопросами в правильном порядке; корень исключён. Генерация не запускалась.

Дополнительные измерения финальной сборки и SHA-256 приведены ниже. Сохранённая пользовательская очередь не запускалась и не отменялась. Полный сквозной запрос OpenAI/TTS, 15-минутное фоновое прослушивание и формальная проверка TalkBack в этой задаче не повторялись. Ограничение перемотки до первого Play после холодного запуска (UI-01) остаётся отдельным открытым пунктом.
