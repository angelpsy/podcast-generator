# Подкасты v2 — этапы реализации и приёмка

Дата: 25 октября 2026 года, Asia/Tbilisi. **Этапы 0–6 завершены; этап 7 остаётся необязательным планом.** Базовая версия зафиксирована коммитом `ac1eaa7`. Требования: [продуктовая спецификация](PODCAST_V2_PRODUCT_SPEC.md). Архитектура и контракты: [техническая спецификация](PODCAST_V2_TECH_SPEC.md). Факты, экспериментальные сборки и границы: [SIWC/TTS/плеер](STAGE0_V2_TEST_2026-10-25.md), [Room/KSP и навигация](STAGE0_COMPATIBILITY_TEST_2026-10-25.md).

## 1. Решения и приоритеты

| Решение | Основание / статус |
| --- | --- |
| Фоновый плеер обязателен | Прямое требование пользователя |
| Фоновая генерация необязательна | Пользователь: желательно без большого усложнения |
| Подробность выбирается для каждого выпуска, по умолчанию подробно | Прямое уточнение пользователя; время не фиксируем |
| Четыре готовые настройки объёма/погружения | Предложение вместо точных минут; объём и глубина меняются отдельно в расширенных настройках |
| Предметно нейтральная структура рассказа | Уточнение пользователя: технические темы, научпоп и другие области; без обязательных блоков «типичные ошибки» или фиксированного числа разделов |
| Топик — дерево, подкаст — самостоятельная запись, плейлист — ссылки | Предложение архитектуры и организации |
| Глубина 1–4, по умолчанию 2; до 200 узлов, до 50 за запрос | Предлагаемые ограничения v2; уточняются на прототипе структуры |
| Один обзор выбранного узла либо пакет по конечным вопросам | Предложение, устраняющее неявную генерацию на всех уровнях |
| Основной сценарий не требует тегов | Поиск по названию обязателен; теги предлагаются тем же ответом и редактируются |
| Тёмная/светлая/системная тема | Тёмная обязательна; выбор системной по умолчанию — предложение |
| Все готовые записи сохраняются | Необходимое изменение прежнего правила «один файл» для библиотеки и плейлистов |

Не требуем дополнительных решений пользователя для подготовки спецификации. Численные лимиты и названия вариантов — настраиваемые проектные значения, а не подтверждённые ограничения Android/OpenAI.

## 2. Этапы

### Этап 0. Узкие технические проверки

До большого UI и без создания всей архитектуры проверить:

1. Текущая SIWC-сессия и выбранная модель возвращают небольшое дерево по JSON Schema. Если формат не поддержан, проверить JSON с локальной валидацией. Зафиксировать реально используемый режим.
2. Supertonic с `lang=en`: обычные фразы и термины HTTP, JavaScript, API, client/server. Проверить понятность на Pixel; русский голос остаётся контрольным.
3. Подробный и углублённый сценарии на технической и научно-популярной теме: фактическое число слов, уместность структуры, время, PSS, размер временных файлов, отмена. На основании результатов уточнить бюджеты из техспецификации. Сравнение всех комбинаций объёма/погружения, включая короткое глубокое объяснение и длинный вводный рассказ, относится к CONTENT-02 этапа 5.
4. Минимальный MediaSessionService: готовый существующий M4A играет при Home и блокировке, pause/resume доступен с lock screen. Нет второго Player из RN.
5. Совместимость Room 2.8.5/KSP и React Navigation с текущим проектом. Зафиксировать версии; не обновлять RN, Kotlin и плеер «заодно».

Результат: все пять направлений этапа 0 проверены. SIWC Schema и контроль enum прошли; английский TTS понятен; длинные M4A на 8:36 и 13:02 созданы; MediaSessionService проверен с блокировкой и app-owned MediaController. Отдельно измерена отмена около 10 с. Room 2.8.5 / KSP2 2.1.20-2.0.1 прошли сборку и тесты миграции, CRUD, rollback и внешних ключей. React Navigation native 7.5.1, native-stack/bottom-tabs 7.21.0, Screens 4.30.0 прошли UI-тесты на Pixel с Fabric/Hermes, Android Back и Activity.recreate. Kotlin/RN/Gradle не обновлялись. Протоколы фиксируют границы проверок и не заменяют приёмку продуктовой v2.

### Этап 1. Библиотека и миграция

Добавить Room, сущности Podcast/AudioAsset/GenerationJob и транзакционную публикацию. Импортировать последний M4A и незавершённый draft из 1.2. Убрать автоматическое удаление предыдущего выпуска. Добавить список записей, простую карточку, удаление, поиск по названию и внешний плеер.

**Завершён в промежуточной 1.3 / versionCode 4.** Несколько самостоятельных выпусков и черновиков хранятся одновременно, переживают перезапуск и не теряют SIWC-сессию. На Pixel перенесены настоящий M4A и незавершённый сценарий из 1.2; продолжение использовало прежний текст. Проверены публикация трёх файлов, поиск, внешний плеер и подтверждённое удаление тестовой записи. 63 JVM, 14 Room и 6 прежних device-проверок прошли. Окна сбоя воспроизводятся управляемым MediaStore поверх реальной Room, а не физическим crash в каждой инструкции. [Полный отчёт и ограничения](STAGE1_LIBRARY_TEST_2026-10-25.md).

`LatestAudioStore` переиспользуется только как протокол одного AudioAsset, со своим Room-журналом на ID. Возвращение к глобальному legacy-хранилищу последнего файла и откат APK до 1.2 небезопасны. Связи топиков/плейлистов и их каскадное поведение ещё относятся к этапам 3–6.

### Этап 2. Постоянный плеер

**Завершён, 1.4 / versionCode 5.** 69 JVM и 31 уникальная Android-проверка прошли; реальное приложение играло 900,6 с с закрытым UI и keyguard, 31/31 samples PLAYING/foreground и 10 переходов. Проверены системные controls, пользователь подтвердил карточку на lock screen, Force stop восстановил очередь на паузе около 71,9 с. Отдельный test APK проверил transient audio focus и автоматическое продолжение. Физическое becoming-noisy, reboot, deep Doze и длительная одновременная генерация остаются границами отдельной итоговой приёмки. [Протокол этапа 2](STAGE2_PLAYBACK_TEST_2026-10-25.md).

Перенести Player в PlaybackService, подключить MediaController, мини-плеер и полный экран. Добавить очередь, seek, предыдущий/следующий, скорость, repeat, сохранение позиции и системные controls. Кнопки экрана не владеют жизненным циклом Player.

Результат: полноценное фоновое прослушивание готовой библиотеки. На Pixel отдельно пройти блокировку, Home, recents, гарнитуру, потерю audio focus, холодное восстановление и отсутствие сети.

**Завершён, 1.5 / versionCode 6.** Room 3 с миграцией 2 → 3; ручной CRUD/перенос/reorder, MAIN/EXTRA, поиск прикрепления, производный плейлист ветки, вкладки и Android Back. 84 JVM и 45 уникальных Android-сценариев прошли. Результат: пользователь может полностью собрать структуру и аудиоподборку вручную, ещё без AI-плана. Это позволяет проверить продуктовую организацию отдельно от качества генерации.

### Этап 4. Генерация структуры

**Завершён, 1.6 / versionCode 7.** Строгий рекурсивный OutlineV1 через прежний SIWC, сохраняемые предложения в Room 4, preview/append/replace и явный повторный просмотр при конфликте. Два реальных ответа gpt-6.1-sol прошли схему и локальную проверку; до Apply новых аудиозаписей нет. В UI проверены холодный запуск, stale/review/discard, применение шести узлов и отмена замены через Home. 94 JVM и 58 уникальных Android-сценариев прошли. [Полный протокол](STAGE4_OUTLINE_TEST_2026-10-25.md).

Ввести OutlineProposal и выбранный на этапе 0 формат ответа. Запросы верхнего уровня и раскрытия ветки; предпросмотр, добавление или замена с подтверждённым diff; optimistic revision check. Действие не создаёт аудио и не меняет дерево до применения.

Результат: большая тема и конкретный вопрос дают редактируемую структуру; ручные правки не теряются при позднем ответе модели. Перезапуск сохраняет уже полученное предложение.

### Этап 5. Профили и управляемая генерация

**Завершён, 1.7 / versionCode 8.** Три профиля, четыре presets и независимые ContentSettings, обзор/выпуск/пакет с preview и per-item overrides. Room 5, постоянная очередь, сохранение сценария и WAV-фрагментов, явное продолжение после паузы/перезапуска, защищённая привязка результата и плейлисты по профилю. 112 JVM и 71 уникальный Android-сценарий прошли. На Pixel готовы RU-simple/EN-simple и подробный RU-standard на 934 слова / 9:21. [Результаты и границы](STAGE5_GENERATION_TEST_2026-10-25.md); полная качественная матрица относится к расширенной приёмке.

Ввести три LanguagePolicy, четыре готовые настройки и ContentSettings с независимыми объёмом, погружением и пожеланием к рассказу. Заменить жёсткий русский prompt на версионированные предметно нейтральные контракты. Добавить обзор узла, одиночный выпуск, пакет конечных вопросов с предварительным списком. Сохранить очередь и checkpoints законченных фрагментов; повторить тесты P-01–P-04 в многозаписной архитектуре.

Результат: выбор профиля и подробности действует на каждый новый выпуск, пакет не дублирует готовые и активные задания. После паузы используется сохранённый текст/аудио. Большая очередь не выполняется параллельно несколькими TTS и не зависит от того, какая вкладка открыта.

### Этап 6. Ручные плейлисты и завершение интерфейса

**Завершён, 1.8 / versionCode 9.** Room 6, ручные списки и независимые копии топиков/веток, языковой фильтр/все профили, явное обновление очереди с сохранением текущего ID/позиции. Три темы с сохранением/native DayNight, обычные настройки аккаунта/модели, release UI без тестовых действий. 112 JVM, 6 Jest и 82 Android-сценария прошли. Pixel: CRUD/copy, холодный запуск, темы ОС/130% шрифт, native Alert, воспроизведение/переход/Pause с блокировкой. [Протокол и границы](STAGE6_PLAYLISTS_THEME_TEST_2026-10-25.md). Полная ручная проверка чтения/жестов TalkBack остаётся отдельной качественной приёмкой, accessibility-дерево/подписи и контраст проверены.

Список обоих типов плейлистов, ручной порядок, добавление из библиотеки, копия плейлиста топика, выбранная ветка как очередь. ThemeProvider и тема native-окон вводятся при создании первых экранов; на этом этапе проводится полный аудит светлой/тёмной темы, шрифтов и TalkBack.

Удалить старые тестовые экраны и публичные диагностические команды из release UI. Сохранить пользовательские настройки аккаунта, языка, модели и хранилища. Отчёты, регрессионные тесты и лицензии остаются в проекте.

Результат: единый интерфейс v2 без вкладки SIWC Spike и без теста голоса. Модель и вход находятся в обычных настройках. Все требования основной версии доступны через продуктовые экраны.

### Этап 7. Необязательная фоновая генерация

После стабильных этапов 1–6 оценить отдельный GenerationService. Проверить типы foreground service, уведомления, квоты, sleep/wake lock, отмену и восстановление. Если это требует значительного изменения JNI/process model, перенести в v2.1; не задерживать фоновый плеер.

Результат принимается только при реальной обработке очереди с заблокированным экраном. Если этап не выполнен, интерфейс честно сообщает, что создание приостанавливается в фоне и продолжается после возврата.

| PLAY-04 | Recents dismissal, process death, reboot, Force stop | Активный FGS переживает обычное закрытие UI; после смерти/перезагрузки доступна сохранённая очередь без автозвука; Force stop не обходится |

Матрица определяет ожидаемое покрытие, а не требует всех комбинаций ручного прогона на каждом коммите. Чистую логику дерева/плейлистов/нормализации покрыть JVM/TS-тестами; транзакции, миграцию, MediaStore и Player — Android instrumentation; сон, звук, уведомления, память и английское произношение — Pixel. Проверять новые риски, не повторять все дорогие генерации после правки документации.

## 4. Выходные артефакты реализации

Для каждого законченного этапа: ограниченный коммит, краткий отчёт проверок, актуальные схемы/контракты и запись новых ошибок в существующий SIWC_ERROR_LOG либо связанный журнал v2. Не переписывать исторические отчёты v1 как будто они проверяют новый код.

Для итоговой сборки: versionName/versionCode и SHA-256 APK, инструкция установки поверх текущего приложения, migration report, матрица фактического покрытия, 1–2 сохранённых эталонных выпуска RU/EN вне Git, описание известных ограничений и статус необязательной фоновой генерации.

## 5. Что сознательно не усложняем

- Нет отдельной модели данных для «модуля» поверх топика/раздела.
- Нет дубликатов M4A ради разных топиков и плейлистов.
- Нет облачной синхронизации, сервера, эмбеддингов и внешнего поиска для базовой версии.
- Нет автоматического перевода или перегенерации всей библиотеки при смене языка.
- Нет бесконечной глубины и запуска сотен записей одной кнопкой.
- Нет обязательной фоновой генерации, чтобы её сложность не задерживала фоновое прослушивание.
