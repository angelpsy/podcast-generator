# Создание подкаста и локальная озвучка

Текущая версия **1.8**: тестовые кнопки удалены из основного интерфейса; ниже сохранена историческая инструкция для прототипа. Обычная генерация, библиотека и экспорт доступны во вкладках, аккаунт/модель — в настройках. Актуальные проверки: [этап 6](STAGE6_PLAYLISTS_THEME_TEST_2026-10-25.md).

**Версия 1.7:** три языковых профиля, выбор объёма/погружения, генерация по узлам и постоянная очередь с сохранёнными фрагментами. Актуальные сценарии, команды и границы — в [протоколе этапа 5](STAGE5_GENERATION_TEST_2026-10-25.md). Далее сохранена инструкция первого русского прототипа.

Главный экран «Подкасты» принимает тему, получает завершённый русский текст через текущую SIWC-сессию, озвучивает Supertonic и сохраняет M4A. Тест фиксированного русского образца без OpenAI оставлен внутри «Выбрать текстовую модель». Контракт: [спецификация](PODCAST_PROTOTYPE_SPEC.md).

Результаты первого запуска, замеры и подтверждение прослушивания: [отчёт Pixel](DEVICE_TTS_TEST_2026-10-25.md).
Результаты следующего этапа с запросом OpenAI: [сквозной тест](DEVICE_PODCAST_TEST_2026-10-25.md).

С версии **1.3** готовые выпуски и независимые черновики хранятся в Room-библиотеке; автоматической замены предыдущего файла больше нет. Удаление — по явному подтверждению в библиотеке. Для миграции, поиска, удаления, 14 новых device-checks и проверки сохранения SIWC используйте [инструкцию и отчёт этапа 1](STAGE1_LIBRARY_TEST_2026-10-25.md). С версии **1.4** готовые записи слушаются в фоне через отдельный сервис, доступны очередь и системные controls: [проверка плеера](STAGE2_PLAYBACK_TEST_2026-10-25.md). Генерация пока требует foreground. Ниже сохранён первоначальный сценарий тестирования одиночной генерации; старые ожидания о единственном файле относятся к 1.1–1.2.

## Подготовка и сборка на Mac

Из корня репозитория:

```sh
source tools/android-env.sh
python3 tools/prepare-tts-assets.py
cd mobile
npm run typecheck
npm run lint
npm test -- --runInBand
cd android
./gradlew :app:testDebugUnitTest :app:lintDebug :app:assembleRelease
```

Скрипт подготовки использует стандартную библиотеку Python, без pip. URL и SHA-256 закреплены в `tools/tts-artifacts.json`. Он проверяет архивы, извлекает только нужные файлы модели и две arm64-библиотеки, сохраняет неизменённый Kotlin binding того же релиза и лицензии. Архивы кэшируются в `.tooling/tts/`, веса и JNI-файлы игнорируются Git. В APK они включены; при запуске сеть для озвучки не нужна.

Используются Supertonic 3 INT8, sherpa-onnx 2.0.0, CPU / 2 потока / 8 шагов / sid 0 / lang ru. Native API получает AssetManager. Полный WAV создаётся в приватном черновике, затем Media3 Transformer 1.11.1 кодирует AAC-LC в M4A. Конечная дорожка проверяется через MediaExtractor, включая AudioSpecificConfig профиля AAC-LC.

## Установка и запуск

Из корня репозитория:

```sh
source tools/android-env.sh
adb devices -l
adb install -r mobile/android/app/build/outputs/apk/release/app-release.apk
adb shell am start -W -n dev.podcast.siwcspike/.MainActivity
```

Установка поверх прежней версии сохраняет SIWC. Приложение открывает «Короткий подкаст»; исходный экран входа, refresh и выхода доступен через «Настройки SIWC». Release-сборка содержит JS bundle и работает без Metro.

1. Разблокировать Pixel, оставить приложение открытым. При необходимости войти через Continue with ChatGPT и вернуться из браузера. Каталог моделей загружается автоматически один раз после входа; при ошибке доступно ручное обновление. Ввести тему (1–500 Unicode code points) и нажать «Создать подкаст».
2. Дождаться подготовки голоса, генерации текста, озвучки фрагментов, сжатия и сохранения. Перед каждым новым текстом каталог проверяется текущей сессией: используется выбранная доступная модель, иначе первая видимая. На время работы приложение удерживает экран включённым; явная блокировка/сворачивание отменяет незавершённую операцию.
3. Проверить «Слушать», «Пауза», «Сначала» и длительность. Первый запуск показывает cold init; следующий в том же процессе использует загруженную модель.
4. Нажать «Открыть в другом приложении» и выбрать совместимый плеер. Запускается ACTION_VIEW с `content://` URI и временным правом чтения; приложение не назначает плеер по умолчанию.
5. Файл лежит в общей папке `Podcasts/PodcastGenerator/`, имеет уникальное имя `podcast-<timestamp>-<id>.m4a`. Он доступен после остановки приложения и выхода из ChatGPT.
6. Создать второй выпуск: после успешного сохранения первого файла приложения в папке быть не должно. При отмене до публикации нового последний готовый файл остаётся. Пользовательские копии и посторонние файлы не очищаются.

## Повтор и диагностика

«Продолжить с сохранённого этапа» повторяет только необходимую работу: запрос текста, если он не завершился; TTS из завершённого сохранённого текста; кодирование из WAV либо сохранение из M4A. Повтор использует тему черновика; отредактированная тема отправляется только через «Создать подкаст». Частичные файлы не публикуются. Journal через AtomicFile позволяет восстановить публикацию и закончить удаление старого URI после перезапуска. Ошибка удаления не отменяет новый готовый файл, но должна быть устранена автоматическим повтором до следующего создания.

Тема, текст и metadata текущего выпуска/черновика хранятся в приватной `noBackupFilesDir`; в общую папку публикуется только M4A с нейтральным именем. Токены остаются в существующем защищённом SIWC-хранилище. Лог `PodcastSpike` использует allowlist: тема, текст, email, URI и токены в него не попадают.

Responses вызывается общим Kotlin-клиентом: `store:false`, `stream:true`, `input` — массив, `instructions` отдельно. До TTS обязательно `response.completed`, непустой текст до 3000 code points и проверка русского текста без управляющих тегов/Markdown. Незавершённый поток, отказ, отмена и превышение лимита не озвучиваются и не повторяются автоматически. [Официальный контракт SIWC](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference), [ограничения](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations).

Тег logcat `PodcastSpike` содержит этапы и численные метрики, без темы, текста ответа OpenAI и токенов. В UI отображаются время текста, подготовка, синтез, кодирование, частота, размер и наблюдаемая PSS. Значение PSS снято в контрольных точках и не является гарантированным пиком памяти.

```sh
adb logcat -s PodcastSpike:I AndroidRuntime:E
```

Автоматические проверки: 59 JVM-тестов — 10 публикации/замены/восстановления, 4 чтения MediaStore Cursor, 4 повтора воспроизведения, 5 доступности сохранённого черновика, 2 WAV, 2 JNI callback, 18 прежних SIWC, 7 Responses streaming и 7 текста/разбиения/повтора/приватности. Jest проверяет приватность SIWC-диагностики. Реальный звук, MediaCodec, доступ внешнего плеера и память подтверждаются отдельно на Pixel. Ошибки и решения: [журнал](SIWC_ERROR_LOG.md).

## Проверки восстановления на Pixel отдельным тестовым APK

Нужна установленная актуальная release-сборка с хотя бы одним готовым подкастом. Завершить генерацию и остановить воспроизведение. Набор использует настоящий AndroidAudioMedia, AtomicFile и ExoPlayer, изолированные journals в cache и собственные временные MediaStore-записи. Сетевых запросов OpenAI нет. Приложение принудительно перезапускается механизмом instrumentation; сессия и готовый выпуск сохраняются.

Из корня репозитория:

```sh
source tools/android-env.sh
cd mobile/android
./gradlew :app:assembleReleaseAndroidTest --offline --console=plain
adb install -r app/build/outputs/apk/androidTest/release/app-release-androidTest.apk
adb shell am instrument -w dev.podcast.siwcspike.test/dev.podcast.siwcspike.podcast.PodcastDeviceChecks
adb uninstall dev.podcast.siwcspike.test
adb shell am start -W -n dev.podcast.siwcspike/.MainActivity
```

Ожидается `result=PASS 6/6; application journal and episode unchanged` и `INSTRUMENTATION_CODE: -1`. Проверять именно этот результат: exit code команды ADB сам по себе не доказывает успех тестов. После запуска в `Podcasts/PodcastGenerator/` должен остаться прежний единственный пользовательский M4A. APK тестов подписан тем же локальным ключом и не включается в release-приложение; новых библиотек для runner нет.

Покрытие и фактический результат: [Pixel после исправлений P-02 — P-04](DEVICE_PODCAST_RECOVERY_TEST_2026-10-25.md). Null-запросы подставляются на границе production reader, физическое заполнение диска и сбой системного провайдера не вызываются.

Незавершённый JNI-вызов отменяется кооперативно. Ограничение TTS в две минуты проверяется в callbacks и между фрагментами, а не посредством принудительного завершения native-потока. Переустановка с удалением данных для этой проверки не нужна.

На первом device-тесте после сворачивания отмена завершилась примерно через 27 секунд. При возврате нужно дождаться завершения «Останавливаем»; последний готовый файл сохраняется. Параметры, память и задержка зависят от состояния устройства.
