# Этап 1: библиотека Room и перенос из 1.2

Дата: 25 октября 2026, Asia/Tbilisi. Устройство: Pixel 10 Pro, Android 17. Промежуточная версия **1.3 / versionCode 4**; application ID и ключ подписи прежние. Установка через `adb install -r`, без удаления приложения или очистки данных.

## Результат

Библиотека хранит несколько самостоятельных выпусков и незавершённых заданий. Есть поиск по названию, выбор записи, просмотр текста, прослушивание, открытие M4A во внешнем приложении и удаление с подтверждением. Создание нового выпуска больше не удаляет готовые записи или предыдущий черновик.

Существующие SIWC-регистрация и токены остались в прежнем защищённом хранилище. Обновление не требует повторного входа. Текстовая генерация, русский голос и короткий формат рассказа сохранены; фоновый продуктовый плеер относится к этапу 2.

## Хранение и восстановление

Room 2.8.5 / KSP2 2.1.20-2.0.1 теперь используются основной сборкой. База `noBackupFilesDir/podcast/library.db`, схема 1 экспортирована в `mobile/android/app/schemas/dev.podcast.siwcspike.podcast.PodcastDatabase/1.json`. Destructive fallback отсутствует.

| Таблица | Назначение |
| --- | --- |
| `podcasts` | ID, название, нормализованное название, порядок создания, DRAFT / READY / FILE_MISSING / DELETING |
| `audio_assets` | Журнал намерения публикации, pending URI, подтверждённые URI и метаданные готового M4A |
| `generation_jobs` | Сохранённый сценарий/настройки/метрики и каталог временных WAV/M4A |
| `migration_state` | Единственный маркер `legacy-v1=complete` |

Для первого этапа метаданные сценария и публикации остаются JSON внутри Room. Это позволяет переиспользовать проверенный протокол `LatestAudioStore` **отдельно для каждого ID**, а не как общее хранилище последнего файла. READY и URI фиксируются в одной транзакции. Перенос URI в отдельные индексируемые колонки возможен следующей явной миграцией, когда появятся запросы плейлистов.

Перед вставкой в MediaStore сохраняется уникальное имя; после insert — URI, после publish — READY. При остановке после insert строка находится по собственному имени и папке; после publish результат подтверждается без второго файла. Null query остаётся ошибкой. Готовые соседние записи не входят в очистку этого задания.

Для удаления сначала сохраняется DELETING. Только после подтверждённого удаления собственного файла и очистки каталога задания удаляется запись с дочерними строками. Незавершённое удаление повторяется при восстановлении. Подтверждённо отсутствующий файл становится FILE_MISSING; новое обращение к OpenAI не запускается.

Новые временные файлы находятся в `podcast/jobs/<id>/`. После успешной публикации удаляются временные файлы и строка задания; готовая запись остаётся. На запуске задания автоматически не продолжаются: пользователь выбирает черновик и нажимает «Продолжить с сохранённого этапа».

## Перенос legacy

1. Проверить форму и прочитать `current.json`, восстановить legacy pending/cleanup по прежнему протоколу. Сбой или некорректные данные не считаются пустой установкой.
2. В одной транзакции импортировать готовый выпуск, незавершённый draft и маркер. Сохранить ID, URI, название, сценарий и метрики. Для импортируемых метаданных обозначить прежний русский короткий контракт как LEGACY, 120–180 слов.
3. Черновик сохраняет ссылку на прежний приватный каталог: не требуется копировать большой WAV/M4A. Уже опубликованный ID не создаёт второй черновик.
4. После маркера `current.json` и `draft/meta.json` больше не являются активными журналами. `current.json` оставлен как резервная метаинформация; каталог legacy draft очищается после успешного продолжения его задания.
5. При ошибке восстановления интерфейс показывает ошибку и кнопку повторной проверки, создание блокируется. SIWC при этом не очищается.

Откат к 1.2 не является безопасным способом восстановления: она снова активирует правило «последний файл» и не знает о библиотеке. Нельзя использовать `pm clear`, uninstall или старый APK для обычного повтора теста миграции.

## Повторить локально

Из корня проекта, с подключённым и разблокированным Pixel:

```sh
source tools/android-env.sh
cd mobile
npm run typecheck
npm run lint
npm test -- --runInBand
cd android
./gradlew :app:testReleaseUnitTest :app:lintRelease :app:assembleRelease :app:assembleReleaseAndroidTest -PlibraryChecks=true
adb install -r app/build/outputs/apk/release/app-release.apk
adb install -r app/build/outputs/apk/androidTest/release/app-release-androidTest.apk
adb shell am instrument -w dev.podcast.siwcspike.test/dev.podcast.siwcspike.podcast.LibraryDeviceChecks
```

Прежние шесть проверок включаются сборкой test APK **без** `-PlibraryChecks=true`, затем `adb install -r` только test APK и запуском `dev.podcast.siwcspike.test/dev.podcast.siwcspike.podcast.PodcastDeviceChecks`. Они требуют сохранённого legacy `current.json` и его исходного M4A: на чистой установке этот старый runner неприменим. Новый LibraryDeviceChecks работает на изолированных fixtures и чистой установке; не обращается к SIWC.

После instrumentation открыть основной экран:

```sh
adb shell am start -W -n dev.podcast.siwcspike/.MainActivity
```

Для ручного повтора: создать несколько выпусков → перезапустить приложение → выбрать старый выпуск → поиск → внешний плеер → удалить только специально созданную тестовую запись. Для проверки пропавшего файла удалить **тестовый** M4A внешним файловым менеджером и нажать «Проверить файлы и восстановление»: запись должна стать недоступной, не создавать аудио заново и не затрагивать соседей.

## Границы этапа

Плеер пока работает только при открытом приложении; нет плейлистов, топиков, тегов, переименования и возобновления позиции. Одновременно выполняется одно задание; сохранённые задания продолжаются вручную, без автоматической фоновой очереди. Библиотека пока выводит весь найденный список без пагинации; перед большим каталогом понадобится постраничная загрузка. Поиск и выбранный выпуск не восстанавливаются как пользовательские настройки: при запуске выбирается самая новая запись. Язык и объём остаются прежними до этапа 5. Тестовые SIWC/голосовые элементы будут убраны на этапе 6.
