## Обнаруженная и исправленная ошибка

Первоначально клиент останавливался с `expected_event_stream`. Безопасная диагностика показала HTTP 200, отсутствующий заголовок Content-Type и фактический формат SSE. Один только Accept-заголовок это не исправил.

Теперь запрос явно указывает `Accept: text/event-stream`. При отсутствии Content-Type клиент допускает SSE только при соответствующем начале тела (`data:`, `event:` или SSE-комментарий). Явно указанный другой MIME-тип, JSON и HTML по-прежнему отклоняются. Успех требует события `response.completed`; Content-Type/sniffing сами по себе успех не подтверждают. Логи содержат только HTTP-статус, MIME-тип/наличие заголовка, классификацию формата и безопасные коды ошибок, без токенов и тела ответа.

Регрессия проверена JVM-тестом: отсутствие заголовка при SSE, корректный MIME с параметрами/разным регистром, отказ для JSON/HTML/явного другого MIME. После исправления 7 Kotlin-тестов проходят, Android lint и release-сборка успешны. TypeScript, ESLint и Jest также прошли при обновлении диагностики.

Успешная попытка по журналу телефона: Streaming 00:18:39 → HTTP 200 00:18:40 → Completed 00:18:41 (Asia/Tbilisi). Текст ответа и подтверждение завершения проверены в UI приложения. ## Повторная авторизация и выход

Безопасная диагностика уточнила исходную ошибку: `UnknownHostException` с причиной `GaiException` на запросе `oauth_token`. Она возникала сразу после callback, когда Chrome оставался на переднем плане. Проверка DNS с телефона в целом проходила. После переноса обмена кода на возврат приложения ошибка на этом устройстве исчезла. Это наблюдение зависимости от состояния приложения; конкретная системная/сетевая политика, вызвавшая отказ DNS в фоне, отдельно не устанавливалась.

Исправление: Kotlin TurboModule передаёт onHostResume/onHostPause в process-owned ForegroundGate. После callback coordinator переходит в AwaitingReturn, хранит одноразовый code только в памяти и ожидает возврата максимум 120 секунд. Затем выполняет token exchange и валидацию, не меняя DNS, TLS и системные ограничения. Отмена прерывает ожидание. Нет автоматического повторного использования одноразового кода.

Выход из приложения не означает выход из самого ChatGPT в браузере — это разные сессии.
