# Этап 6: ручные плейлисты, темы и обычный интерфейс

Дата: 25 октября 2026, Asia/Tbilisi. Android **1.8 / versionCode 9**, Pixel 10 Pro / Android 17. Обновление поверх 1.7, с прежним applicationId и ключом, без очистки данных. Сценарии и озвучка для этого этапа заново не запрашивались.

## Реализовано

Три вкладки: «Топики», «Подкасты», «Плейлисты». Настройки открываются из верхней панели. Общий мини-плеер сохраняется на вкладках и в настройках; Android Back и явные переходы возвращают к спискам. Приложение в launcher называется Podcast Generator; внутренний package/React component сохранены для совместимости.

Ручной плейлист: создание, переименование, добавление через поиск библиотеки, удаление ссылки, перестановка кнопками «Выше/Ниже», удаление списка с подтверждением. В списке показываются профиль, длительность и доступность записи. Один podcast ID включается один раз, один файл может присутствовать в нескольких списках. FILE_MISSING остаётся виден, но не входит в новую очередь. До 1000 ссылок в плейлисте.

В общей вкладке видны и ручные списки, и производные плейлисты топиков. Для топика/ветки выбираются текущий язык либо все профили. «Скопировать в свой плейлист» фиксирует текущий порядок и ссылки, включая видимые недоступные записи; файлы не копируются. Копия дальше не зависит от дерева. Изменение структуры во время копирования проверяется по revision. Копия доступна как из режима «Слушать» топика/ветки, так и из общего каталога.

Запущенная очередь — отдельный снимок IDs. Редактирование, удаление плейлиста, фильтра или топика не обрывает звук. «Слушать» начинает новый список; явное «Обновить очередь» применяет новые IDs, сохраняет текущую запись/позицию, если она есть в новом наборе, и сохраняет play/pause. Если текущей записи больше нет, выбирается первая. Обновление пустым/полностью недоступным списком отключено: старый снимок не стирается случайно.

Оформление: светлое, тёмное, системное (default), сохраняется на диск. Палитра применяется к карточкам, тексту, полям/placeholder/selection, кнопкам, модальным формам, навигации, мини-плееру и полному плееру. Для native-окон используется существующий AppCompat.DayNight с MODE_NIGHT_FOLLOW_SYSTEM/NO/YES, режим восстанавливается до onCreate. Это локальная тема приложения, а не изменение темы ОС; [Android DayNight](https://developer.android.com/develop/ui/views/theming/darktheme), [локальная альтернатива UiModeManager](https://developer.android.com/reference/android/app/UiModeManager#setApplicationNightMode(int)). SharedPreferences сохраняют выбор, AppCompat применяет его в процессе. Отдельная гарантия совпадения системного splash до запуска Activity не заявляется.

Кнопки имеют минимум 48 dp, перенос текста и доступные подписи/selected/disabled. Мини-плеер сообщает название записи в accessibilityLabel. Цвета активного и неактивного текста вкладок заданы явно, чтобы не использовать слишком бледный стандартный inactive tint. Основные текстовые цвета/подсказки/ошибки и кнопки проверяются на контраст не ниже 4.5:1. Disabled controls — отдельное визуальное состояние.

Настройки: аккаунт/подписка ChatGPT, подключение/выход, текущий каталог и выбор модели, defaults языка/объёма/погружения/акцента/аудитории новых отдельных выпусков, папка M4A. Последняя модель из legacy input.json подхватывается при отсутствии нового значения. Собственные настройки топиков и задания в очереди не переписываются. Каталог моделей загружает один общий bootstrap; вход/выбор модели остаются в настройках. Форма генерации показывает выбранную модель. Временный сетевой/авторизационный сбой не запускает новый сценарий скрыто.

Из release UI удалены SIWC Spike, тестовый запрос/ответ, ручной refresh, тест голоса, экспорт диагностики, HTTP/JSON/PSS и внутренние времена этапов. Остались пользовательские ошибки/прогресс, число слов, длительность/размер файла и «Обновить библиотеку» для сверки MediaStore. Исторические отчёты, unit/instrumentation и отдельный stageZero variant сохранены; скрытого тестового меню в основном приложении нет.

## Данные и миграция

Room **6**, новая миграция **5 → 6**, цепочка **1 → 2 → 3 → 4 → 5 → 6**, без destructive fallback. Новые таблицы:

| Таблица | Поля/инварианты |
| --- | --- |
| playlists | UUID, title, revision, createdAt, updatedAt |
| playlist_entries | composite PK playlistId/podcastId, position; FK к плейлисту и Podcast с CASCADE; индекс podcastId |

Мутации транзакционны и сравнивают expectedRevision. Повтор add того же ID ничего не меняет. Удаление Podcast после подтверждённого удаления его файла меняет revisions затронутых плейлистов и удаляет их ссылки вместе с прежними связями топиков. Удаление только плейлиста/ссылки не трогает Podcast/AudioAsset/GenerationJob или текущую очередь.

Настройки хранятся отдельно в app-preferences SharedPreferences, с синхронным подтверждением записи и валидацией допустимых полей/профилей. OAuth не переносится в эти настройки или Room. Смена темы не вызывает повторного входа. Новых библиотек/моделей и разрешений на медиатеку не добавлено.

## Автоматические проверки

- **112 JVM**, прежняя регрессия сценариев, SIWC, файлов и очереди: без ошибок.
- **6 Jest**, три suites: контраст обеих палитр, системный/явный выбор, неизменность layout при смене цветов, отсутствие диагностических действий/маршрутов в release UI и прежняя защита диагностики. TypeScript/ESLint прошли.
- **12 LibraryUIDeviceChecks**: миграция 5 → 6 с библиотекой/черновиком/checkpoint/предложением/playback/настройкой языка; CRUD без удаления аудио; duplicate-add/две коллекции; порядок/remove/re-add; stale/invalid mutations; FILE_MISSING/DRAFT; удаление Podcast с revision/cascade и только его URI; фильтр/копия/независимость от топика; stale copy; preferences/legacy model; reopening; настоящий MediaSession.
- **70 регрессионных Android-сценариев**: Generation 13 (12 storage + настоящий TTS сохранённого сценария без Responses), Outline 12, Topic 14, Library 14, Playback 11, прежний Podcast 6. **Всего 82 уникальных сценария текущей сборки.** Старые live-запросы из этапа 5 заново не отправлялись и в это число не включены.

Нативный MediaSession-тест запустил две реальные записи, переставил список без изменения активного снимка, затем явным update применил новый порядок с прежним playing ID/позицией. Удаление ссылки/плейлиста, Activity.recreate и Home на пять секунд не оборвали звук; аудиожурналы совпали. Новые наборы выполняются на временных БД, production-проверка создаёт и удаляет только свой временный плейлист.

## Проверка обычного UI на Pixel

Создан Pixel audio, через поиск HTTP добавлен подробный выпуск; после очистки поиска добавлен английский выпуск. Плейлист переименован в **Pixel learning**, английский перемещён выше русского. Открыт диалог удаления записи и отменён: обе ссылки остались. Проверены тёмные поле/форма, карточки, навигация, плеер и native Alert.

Из производного плейлиста «Свет и звёзды» включены все профили, создана **Stars copy** с двумя ссылками. После холодного запуска оба ручных списка имели по две записи. Временная Stars copy затем удалена через подтверждение UI; Pixel learning и аудио сохранены. Топики остались на месте.

При системной тёмной теме выбрана светлая тема приложения, после Force stop она восстановилась. Далее выбран System: при OS night=no приложение светлое, при night=yes тёмное. Проверен системный font_scale 1.3: главные кнопки, вкладки, заголовки и мини-плеер доступны, длинный контент прокручивается. В конце возвращены исходные night=yes и font_scale=1.0, в приложении оставлено System. Снимки light/dark/native-dialog/large-font сохранены только в локальных игнорируемых артефактах.

## Границы

Проверены accessibility-дерево/подписи, selected/disabled, минимальные touch targets, контраст и шрифт 130%. Полная ручная навигация с озвучиванием TalkBack и пользовательскими жестами не выполнялась; формальная accessibility-сертификация не заявляется. Плейлист с 1000 записей не использован для длительного нагрузочного UI-бенчмарка. Повтор полного 15-минутного фонового теста этапа 2 не требовался; сервис/аудиокодек не заменены.

Создание по-прежнему foreground-only и при уходе в фон ставится на паузу. Обязательные функции этапов 0–6 реализованы; GenerationService при заблокированном экране остаётся необязательным этапом 7. Экспорт отдельного M4A сохранён; внутренний плейлист не экспортируется автоматически в сторонний плеер.
