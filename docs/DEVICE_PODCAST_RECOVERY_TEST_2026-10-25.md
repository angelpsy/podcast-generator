## Проверка исправленных сценариев на устройстве

Использован [PodcastDeviceChecks](../mobile/android/app/src/androidTest/java/dev/podcast/siwcspike/podcast/PodcastDeviceChecks.kt), отдельный instrumentation APK размером 39 888 байт. SHA-256 тестового APK: `2ec23d013ad7a0dd25fcc632641c318e30158b1b94612a0c1073c71e9856a08e`. Приложение при этом осталось тем же release APK.

| Проверка | Что выполнено на Pixel и что подтверждено |
| --- | --- |
| P-02: null при проверке публикации | Настоящие MediaStore-вставка, копирование и публикация; искусственный отказ записи commit в изолированном journal. Затем null передан в production `AudioMediaRows.isPublished`. Восстановление сохранило pending и опубликованный новый файл; после снятия отказа новый стал current, старый удалён, повтор не создал дубликатов. |
| P-02: null при проверке владельца | Production reader получил null во время очистки. Cleanup остался в journal, следующая генерация заблокирована до новой вставки. После снятия отказа старый файл удалён, новый сохранился. |
| P-02: null поиска после insert | Искусственная остановка после настоящего insert, до сохранения URI. Null при поиске сохранил pending и незавершённую строку. Следующее восстановление нашло и удалило её, сохранив предыдущий готовый файл. |
| P-03: ошибка настоящего ExoPlayer | Плеер прочитал некорректный временный аудиофайл, вызвал `onPlayerError` и перешёл в STATE_IDLE. Байты заменены на корректный WAV по тому же URI; production `playPodcast` восстановил воспроизведение. Также подтверждены продолжение с прежней позиции после паузы и старт сначала после STATE_ENDED. Тестовый звук заглушён. |
| P-04: отказ первой записи metadata | Настоящий AtomicFile не смог создать файл из-за контролируемого конфликта пути в тестовом cache. `PodcastDraft.resumable` вернул null. Устранение причины само по себе не включило повтор; только успешная новая запись сделала черновик доступным. Уже опубликованный id исключается. |
| P-04: отказ обновления сохранённого черновика | После сохранения русского текста заблокирована следующая запись `.new`. Production reader вернул прежний текст; после устранения препятствия следующая запись и чтение успешны. |

Итог повторного полного запуска: **PASS 6/6**, `INSTRUMENTATION_CODE: -1`. После набора побайтово проверены неизменность основного `current.json` и готового M4A. Все созданные тестом MediaStore-записи удалены; в общей папке остался только пользовательский выпуск. Тестовый APK удалён, обычное приложение возвращено на экран последнего файла, воспроизведение остановлено. При заключительной проверке экран телефона уже был заблокирован. SIWC-сессия сохранилась. Тесты не обращаются к SIWC-хранилищу и не вызывают OpenAI.

В первом запуске прошли 5 из 6 проверок; шестая остановилась на ошибочном утверждении теста о самостоятельном удалении `.new`. `AtomicFile.openRead` уже удаляет эту запись при наличии основного файла ([исходник Android](https://android.googlesource.com/platform/frameworks/base/+/master/core/java/android/util/AtomicFile.java#259)). Проверка очистки исправлена, после чего весь набор прошёл. Изменения production-кода не понадобились. Первоначальный и итоговый вывод сохранены в `.tooling/tts/podcast-device-checks-initial.txt` и `podcast-device-checks.txt`.

## Границы

Это управляемые проверки отказов на настоящем устройстве. Null от системного провайдера не вызывался принудительным падением MediaStore: в трёх проверках он подставлен на границе production reader, остальные операции выполняет настоящий AndroidAudioMedia. Приватные записи изолированы в тестовом cache; основное хранилище подкаста не повреждалось. Физическое заполнение диска и отказ записи через основной UI не воспроизводились; доступность черновика проверена production-предикатом на реальном AtomicFile. Настоящая ошибка плеера вызвана повреждённым тестовым контейнером, а не аппаратным сбоем декодера.

Отдельный сценарий прерывания TTS и продолжения без нового Responses-запроса в этом проходе не повторялся; его прежний результат относится к [предыдущей сборке](DEVICE_PODCAST_TEST_2026-10-25.md). Фоновое воспроизведение, произвольные темы и длительный термотест остаются вне этой проверки.
